# PBTools: reverse-engineering, porting and rebuilding notes

Target: IRRI **PBTools 1.1** (Plant Breeding Tools; Eclipse RCP Java GUI over R 2.15.1 through JRI), source from github.com/aagulles/STAR and the installed R package at `C:\RPackages\R-2.15.1\library\PBTools`.
Scope (user decision, 2026-11-03): only the **Phenotypic Analysis** menu: single environment; multi-environment (one-stage, two-stage); GxE (stability models, multiplicative models). QTL, diallel, North Carolina, generation means, randomization and selection index are out of scope.

Approach (user decision, 2026-11-03): like STAR -> RDstat (github.com/kanthjs/STAR-Rev), but the app computes with **published R packages** (lme4, emmeans, multcomp, nlme, metan) instead of PBTools' functions. The PBTools code, ported to modern R, stays as the yardstick: every engine result is compared with it.

## How PBTools works

Menu item -> Java handler -> dialog -> manager in `RJavaManager1.0.jar` (`PBToolAnalysisManager`), which builds R command strings and evaluates them through JRI: `read.csv` into `data`, `sink()` to a text file, `ssa.test(...)`, `GEOneStage.test(...)`, `GETwoStage.test(...)`, `stability.analysis(...)`, `multiplicativeModels(...)`, `ssa.pairwise(...)`. `initPBtool()` runs `library(PBTools)`. All statistics are in the R package; the Java side only formats calls and output.

## Provenance check (2026-11-04)

Question: do the reference sources match the PBTools installed at `C:\PBTools`?

Menu. `Application.e4xmi` in `C:\PBTools\plugins\Star_1.0.0.201406021442.jar` (PBTools is the same Eclipse code base as STAR, product `Star.product`) has Analysis > Single-environment Analysis; Multi-environment Analysis > One-Stage, Two-Stage, GxE Analysis > Stability Models, Multiplicative Models; plus Selection Index, QTL, Mating Designs, Generation Mean. The first five are the scope of this project.

R functions. The shingocat fork (`reference/pbtools-r-fork`) was compared with `reference/r-original` (deparsed from the installed `C:\RPackages\R-2.15.1\library\PBTools`) by parsing both and comparing the deparsed functions. Of 63 functions in both, 58 are identical. In scope, identical: `ssa.pairwise`, `ssa.resid`, `GEOneStage_resid`, `GETwoStage_resid`, `GETwoStage.dataRecode`, `stability.analysis`, `multiplicativeModels`, `ammi.analysis(2)`, `gge.analysis(2)`, `AMMI.contour`, `genoNpheno.corr`, `DescriptiveStatistics`. Different: `ssa.test`, `GEOneStage.test`, `GETwoStage.test` (only lme4 1.x accessors, `@coefs` -> `$coefficients`, `@REmat` -> `$sigma^2`, and one heading text), plus `trimStrings` and `graph.mea1s.diagplots` (no effect on results). The fork has 99 functions that the installed package does not have (`doSEA`, `doMEA`, contrasts, QTL, ...): a later development version. The port (`reference/pbtools-port`) is built from `r-original`, not from the fork, and differs from it only in the five functions changed on purpose (see "Changes made in the port"). The yardstick is therefore the installed PBTools.

Java bridge. The installed bridge is `lib/RJavaManager1.0.jar` inside the plugin (md5 `1846cb4e04396665b011b0feebf43e24`, same file as `configuration/org.eclipse.osgi/bundles/1/1/.cp/lib/`). Its class files were read directly (constant pool: string literals and method names) and compared with `reference/java-rbridge`: all 18 classes, all 950 strings of `PBToolAnalysisManager` and all its 31 methods are present in the repo sources. The repo sources (decompiled from STAR's jar) contain more: `doSingleEnvironmentAnalysisPRep` (`ssaTestPrep`), `doOutlierDetection`, `doSingleEnvironmentAnalysis2`, linear / nonlinear / PLS / factorial regression, and, inside the single-environment and one-stage dialogs, the Augmented Alpha-Lattice and Augmented Row-Column designs, an lmerTest F table, `contrastAnalysis` and the object-based `doMEA` calls. These belong to the later version; PBTools 1.1 does not have them. The randomization and design managers also differ (argument names, e.g. `check` vs `numCheck`), outside the scope. The engine, app, scripts and docs use none of the later-version features.

Open: (1) decompile the installed jar (`java -jar cfr-0.152.jar RJavaManager1.0.jar --outputdir reference/java-rbridge`) and replace the STAR sources; (2) confirm which R the GUI loads (no R path is stored in the jars; likely the install4j launcher or PATH / registry), expected `C:\RPackages\R-2.15.1`.

## Engine on packages (what replaces what)

| PBTools function | Engine | Package calls | Result vs PBTools |
|---|---|---|---|
| `ssa.test` (7 designs, fixed / random, excludeCheck) | `pb_sea` | `lme4::lmer` with the PBTools design terms, `emmeans::emmeans(lmer.df = "asymptotic")`, `coef()` for BLUPs, `anova(refit = FALSE)` for the LRT | identical (BLUE, SE, BLUP, H2, LRT) |
| `DescriptiveStatistics` (dialog option "Descriptive statistics": nnmiss, mean, sd; by environment in single environment, `grp = NULL` in one-stage and two-stage) | `pb_descriptive` | base R | identical |
| `ssa.pairwise` | `pb_pairwise` | default `emmeans::contrast` (Tukey-Kramer, `dunnettx`); `method = "multcomp"`: `multcomp::glht` single-step, as PBTools; letters by `multcompView::multcompLetters` (not in PBTools) | multcomp: identical intervals with the same seed; emmeans: same pairs and differences, interval widths within 1% (identical for balanced data) |
| `GEOneStage.test` | `pb_one_stage` | lme4, emmeans, `predict(re.form)` for GxE means | identical |
| `GETwoStage.test` | `pb_two_stage` | lme4 with weights, emmeans | identical (in lme4 1.x terms, see below) |
| `stability.analysis` regression | `pb_fw` | `metan::ge_reg` | identical slopes; metan reports s2di = PBTools MSDev - pooled error / reps |
| `stability.analysis` shukla | `pb_shukla` | `metan::Shukla`; PBTools form with `nlme::gls(varIdent)` | PBTools form identical; metan uses Shukla's (1972) formula (different statistic) |
| (not in PBTools) | `pb_stability_stats` | `metan::ge_stats` | - |
| `ammi.analysis(2)` | `pb_ammi` | `metan::performs_ammi` | % per PC and scores identical; F of PCs slightly different (raw-data error vs stage-1 pooled error) |
| `gge.analysis(2)` | `pb_gge` | `metan::gge` | % explained identical |

Notes:
- emmeans applies the Kenward-Roger adjustment to lmer fits by default; `lmer.df = "asymptotic"` gives the model-based SE that PBTools reports.
- multcomp finds the critical value of simultaneous intervals numerically (randomised); `pb_pairwise(seed = 1)` makes them reproducible.
- statgenSTA / statgenGxE were also tested (docs/PACKAGES.md): statgenSTA treats replicates as fixed (other SE) and has no augmented or latinized designs; gxeFw estimates environment effects jointly (other slopes). They are not used.

## Changes made in the port (`reference/pbtools-port`, relative to the recovered sources)

1. `summary(m)@AICtab`, `@coefs`, `@REmat` (lme4 0.999) replaced by `AIC/BIC/logLik`, `coef(summary(m))`, `attr(VarCorr(m), "sc")^2`.
2. `||` on vectors (R 4.3 error) -> `anyNA(match(...))` in argument checks.
3. Text read as character since R 4.0: `GEOneStage.test` converts environment and genotype to factors.
4. `mean(data.frame)` is NA since R 3: heritability in `GEOneStage.test` uses the count column.
5. `anova()` columns renamed to the old layout.
6. Dependencies copied from the original (`DescriptiveStatistics`, `printDataFrame`, `DataAttribute`, moments, ...); `scripts/find_missing.R`, `scripts/gen_namespace.R`.
7. `pb_wrappers.R`: structured front end used by the first app version (superseded by `engine/`).

## Known differences from PBTools 1.1 (old lme4 / nlme), all documented in the app's Methods page

- **Weighted two-stage (1/SE²)**: old lme4 scaled the random-effect variances and the SEs of means by 1/mean(w) (x3502 and x59 in the example). **Decision (user, 2026-11-03): follow lme4 1.x.** Means agree.
- **LRT of a fixed genotype term (one-stage)**: old lme4 stopped at a worse ML optimum (logLik -182.31 vs -181.11; Chisq 22.6 vs 25.0).
- **Singular fits**: old gives exactly 0, new 1e-3..1e-8 for a variance on the boundary; p-values of LRTs with Chisq ~ 0 differ (0.915 vs 0.9999).
- **Shukla interval bounds** differ between nlme 3.1-104 and 3.1-168; estimates agree.
- **Original bugs kept in the port**: genotype fixed with `excludeCheck = TRUE` stops with "object 'newExcludeCheck' not found" (the engine and app offer excludeCheck only with genotype random); the latinized row-column design requires row numbers that continue across replicates.

## App (prototype/app)

Screens: Home, Single environment, Multi-environment, GxE & stability, Info (Methods, About). Each screen: sidebar of numbered steps (design, data, variables, genotype effect, advanced options) with a sticky Run button; tabs Results (key numbers, Thai summary, result cards with copy buttons), Mean comparison (Tukey / Dunnett, letters), Plot, Assumptions (PBTools residual plots + Shapiro-Wilk), Data; Excel and Word downloads; results greyed out when the settings change (as RDstat). Examples: PBTools data (RCB 15 x 11 sites, RCB 8 x 2 sites, stage-1 means) and simulated layouts for the other designs.


Changes after the first version (see CHANGELOG.md):
- Single-environment screen: RCBD only (user decision, 2026-11-03); the engine keeps the seven designs and their checks.
- Speed: `multcomp` single-step intervals take about 3 s per site with 15 genotypes, and `multcomp::cld` another 17 s (both compute the multivariate t critical value numerically), so Tukey for 11 sites took 5 minutes. The default is now emmeans (studentized range / Dunnett approximation) with letters from multcompView: 1.6 s for 11 sites. `scripts/timing.R` times every analysis; the slowest left is `metan::ge_stats` (about 8 s natively), and in the browser everything runs several times slower than native R.
- Examples: the simulated alpha-lattice, row-column and latinized row-column layouts used by `designs_cases.R` are not valid designs (genotypes repeated within a replicate); they stay as computational test data for the port, but are no longer offered in the app. The multi-environment row-column example is a valid 5 x 5 design (two orthogonal latin squares), checked by `scripts/check_examples.R`.

Not done: deployment (workflow in `.github/workflows/pages.yml` not yet run), Thai text review, timing in the browser (metan pulls many packages), the GGE / AMMI plot options beyond the ones listed in the app.
